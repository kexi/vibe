通过 `.vibe.local.toml` 文件，你可以用个人设置覆盖或扩展共享的 `.vibe.toml` 配置。该文件会自动被 gitignore。

## 使用场景

- 开发者专属的环境文件
- 本地路径或凭据
- 个人工作流定制
- 特定机器的配置

## 基本示例

```toml
# 用本地命令覆盖或扩展共享钩子
[hooks]
post_start_prepend = ["echo '本地设置开始'"]
post_start_append = ["npm run dev"]

# 覆盖需要复制的文件
[copy]
files = [".env.local", ".secrets"]
```

## 配置合并

数组字段会先在各自的文件内解析，然后再跨文件合并。当 `.vibe.toml` 和 `.vibe.local.toml` 同时存在时，`.vibe.local.toml` 会按照以下规则合并到共享文件之上：

| 方式     | 语法                     | 说明                                                                     |
| -------- | ------------------------ | ------------------------------------------------------------------------ |
| 完全覆盖 | `字段名 = [...]`         | 完全替换共享的值（同一文件内的 `_prepend` / `_append` 仍会在其前后添加） |
| 前置追加 | `字段名_prepend = [...]` | 在共享值之前添加条目                                                     |
| 后置追加 | `字段名_append = [...]`  | 在共享值之后添加条目                                                     |

### 合并示例

```toml
# .vibe.toml（共享）
[hooks]
post_start = ["npm install", "npm run build"]

# .vibe.local.toml（本地）
[hooks]
post_start_prepend = ["echo '本地设置'"]
post_start_append = ["npm run dev"]

# 结果: ["echo '本地设置'", "npm install", "npm run build", "npm run dev"]
```

### 覆盖示例

要完全替换共享配置：

```toml
# .vibe.local.toml
[hooks]
post_start = ["my-custom-script.sh"]

# 结果: ["my-custom-script.sh"]
# （共享的 post_start 被完全替换）
```

### 单个文件内的合并

`_prepend` / `_append` 并不局限于 `.vibe.local.toml`。它们在单个文件内同样生效，因此只有 `.vibe.toml`（没有 `.vibe.local.toml`）的仓库也可以使用。在一个文件内，实际生效的数组为 `prepend + 字段 + append`：

```toml
# 仅有 .vibe.toml —— 没有 .vibe.local.toml
[copy]
files = [".env"]
files_append = [".env.local"]

# 结果: [".env", ".env.local"]
```

每个文件都会先按这种方式解析，然后 `.vibe.local.toml` 才会合并到共享文件的实际数组之上（本地的 `字段` 会替换它，本地的 `字段_prepend` / `字段_append` 会在其前后添加）。

:::caution
`files = []` 是禁用列表的惯用写法，但同一来源中的扩展字段依然生效：`files = []` 与 `files_append = ["x"]` 同时存在时，结果是 `["x"]` 而不是 `[]`。如果希望得到空结果，请一并删除 `_append` 行。
:::

## Worktree 路径覆盖

你可以在 `.vibe.local.toml` 中覆盖 worktree 路径脚本：

```toml
# .vibe.local.toml
[worktree]
path_script = "./my-local-path-script.sh"
```

它的优先级高于 `.vibe.toml` 中的 `path_script`。

## 信任注册

与 `.vibe.toml` 一样，本地配置文件也必须经过信任注册：

```bash
vibe trust
```

该命令会同时信任 `.vibe.toml` 和 `.vibe.local.toml`（如果存在）。

## 完整示例

```toml
# .vibe.local.toml

[copy]
# 追加仅本地使用的复制文件
files = [".env.local", ".secrets", "local-config.json"]

[hooks]
# 在共享的 pre_start 钩子之前执行
pre_start_prepend = ["echo '开始本地设置'"]

# 在共享的 post_start 钩子之后执行
post_start_append = [
  "npm run dev",
  "open http://localhost:3000"
]

# 完全覆盖 pre_clean
pre_clean = ["echo '自定义清理'"]
```
